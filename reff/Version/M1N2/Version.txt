M1N2
============
本仕様書はLicense.txt M1N0に従うものとします。

本仕様書では、バージョンの表し方についてを纏めています。独自色が強すぎる所為。


基本
------------
バージョンはMxNyPzRで記述します。

	M :=: Major or Make specification
	N :=: miNor or Note specification or Mの次の文字って、Nだよね
	P :=: Patch or Patch software
	R :=: Release code


バージョン番号
------------
MはMajor番号であり、仕様策定によって新たな仕様になった際に変更します。新規開発では1を割り振ります。

NはmiNor番号であり、仕様改定、仕様の修正・調整によって仕様変更が起きた際に変更します。新規開発では0を割り振ります。

PはPatch番号であり、コードの修正が行われた際に変更します。新規開発では0を割り振ります。
- その為仕様書にはP番号は記述されません。
- またP番号が変更されたからと言ってそれ迄のP番号が仕様的に無効になる事もありません。
  これはそのP番号も仕様に準拠しようとしていたが問題点があったと言う意味である為です。
  裏を返せば、P番号が最新であるからと言って完全に仕様に準拠していると言う意味でもありません。
  その時点で仕様に準拠している、今の所準拠しているだけに過ぎません。

尚、バージョンは衝突してはなりません。軽微な修正であったとしても、唯のコード修正に過ぎなかったとしても、何かしらの影響が出るならばそれは新しいバージョンです。
その為リリース1やリリース2と言う概念は存在しません。
- コメントの修正や、コードフォーマットの修正程度の影響が出ない修正であればバージョンは変わりません。
  この時同じバージョンが複数存在する事にはなりません。これは同じバージョンの衣装違いではなく、本来存在しない記憶が存在してしまっていただけ、の様な状態であると解釈する為です。


リリースコード
------------
リリースコードはコードに付く目安です。仕様書にはリリースコードは付きません。

リリースコードには以下の何れかが割り振られます。

	P :=: Pre alpha
	A :=: Alpha
	B :=: Beta
	M :=: Master release

PはPre alphaであり、開発初期である、かなり不安定であると思われる際に付けられます。

AはAlphaであり、PAよりかは安定しているもののまだ不安定であると思われる際に付けられます。

BはBetaであり、Aよりも安定しており不安定な場合の方が少ないものの、未だ不安定なところが多いと思われる際に付けられます。

MはMaster releaseであり、基本的には安定版として付けられます。

但しこれらはあくまで感覚的な物に過ぎず、MRでも不安定である、Aでも安定的である場合があります。
また、リリースコードには新規開発時に割り振る可き物は存在しません。飛び級も許されるし、降ろす事も出来ます。

尚、リリースコードはバージョン番号を決めた後に付けます。
